Claude Code

CallLint support for Claude Code by Anthropic. CallLint scans MCP server entries only. Skills, hooks and permission settings in the same file are not covered.

P0 Auto-detects

Why scan Claude Code?

Claude Code grants an MCP server the same shell, filesystem and plugin reach the agent itself has, and its settings file is shared with skills and hooks — so one unreviewed server entry inherits the whole working directory.

Usage

CallLint can auto-discover and scan Claude Code configurations:

calllint scan --agent claude-code

How to start

Install nothing globally — run CallLint straight from npm:

npx calllint scan --auto

Then scan Claude Code specifically:

calllint scan --agent claude-code

How to verify it worked

Read the verdict line for each server. Anything not SAFE names the evidence that produced it, so the next step is to open that server’s command and confirm the authority it asks for is authority you meant to grant.

What CallLint does to Claude Code

Offline by default. Deterministic. Never executes the server it judges. SAFE means no blockers observed, not a proof of runtime safety.

A No blockers observed verdict means exactly that — no blocker under the evidence CallLint could collect. It is not a guarantee, and Insufficient evidence never becomes it on its own. See Coverage Boundary for what this scan does not look at.

Configuration Paths

CallLint looks for Claude Code configurations in:

  • ~/.claude/settings.json
  • <project>/.claude/settings.json

Authority Surfaces

Claude Code can grant tools the following authority surfaces:

  • mcp
  • filesystem
  • shell
  • plugins
