OpenAI Codex

CallLint support for OpenAI Codex by OpenAI. CallLint does not yet auto-discover Codex configuration. The config path is documented but no extractor reads TOML, so Codex servers must be passed explicitly.

P2 Guide only

Why scan OpenAI Codex?

Codex is a local coding agent holding shell, file-patching and plugin authority in the same session, so an MCP server registered in its config.toml is reachable from a process that can already edit your working tree and run commands in it.

Usage

CallLint does not yet support native auto-discovery for OpenAI Codex. No automatic detection yet — this page documents where the config lives.

What CallLint does to OpenAI Codex

Offline by default. Deterministic. Never executes the server it judges. SAFE means no blockers observed, not a proof of runtime safety.

A No blockers observed verdict means exactly that — no blocker under the evidence CallLint could collect. It is not a guarantee, and Insufficient evidence never becomes it on its own. See Coverage Boundary for what this scan does not look at.

Configuration Paths

CallLint looks for OpenAI Codex configurations in:

  • ~/.codex/config.toml
  • $CODEX_HOME/config.toml

Authority Surfaces

OpenAI Codex can grant tools the following authority surfaces:

  • mcp
  • tools
  • filesystem
  • shell
  • plugins

Distribution

CallLint is available for OpenAI Codex through:

  • mcp-stdio (via officialMcpRegistry) — Listing not yet verified
  • openai-plugin — Not available here
    ⚠️ Do not create remote MCP just for public listing eligibility
