Kiro

CallLint support for Kiro by AWS. CallLint does not yet support Kiro native discovery.

P2 Guide only

Why scan Kiro?

Kiro grants MCP servers filesystem and shell authority from a project-local config, so a server entry can arrive with a cloned repository.

Usage

CallLint does not yet support native auto-discovery for Kiro. Support is not implemented yet — this page documents what we can observe today.

Configuration Paths

CallLint looks for Kiro configurations in:

  • .kiro/settings/mcp.json
  • ~/.kiro/settings/mcp.json

Authority Surfaces

Kiro can grant tools the following authority surfaces:

  • mcp
  • filesystem
  • shell

Distribution

CallLint is available for Kiro through:

  • mcp-stdio (via officialMcpRegistry) — Listing not yet verified
  • kiro-workspace-config — Listing not yet verified
    Config paths are now documented by the vendor; a thin adapter for the mcpServers JSON is evaluable but unbuilt. Support stays unimplemented until a discovery adapter exists and is fixture-covered.

Support Status

Guide only — Support is not implemented yet — this page documents what we can observe today.

CallLint publishes no scan command for Kiro yet. That is a statement about CallLint's coverage, not about Kiro: see Coverage Boundary for what would have to be built first.
