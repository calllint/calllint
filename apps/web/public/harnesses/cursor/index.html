Cursor

CallLint support for Cursor by Anysphere. CallLint scans MCP server entries only. Cursor rules and editor settings are not covered.

P0 Auto-detects

Why scan Cursor?

Cursor gives MCP servers shell and filesystem authority inside the repository you have open, and `.cursor/mcp.json` is commonly committed — so a server entry travels to every collaborator who opens the project.

Usage

CallLint can auto-discover and scan Cursor configurations:

calllint scan --agent cursor

How to start

Install nothing globally — run CallLint straight from npm:

npx calllint scan --auto

Then scan Cursor specifically:

calllint scan --agent cursor

How to verify it worked

Run it against the project config as well as the user one. A committed `.cursor/mcp.json` is a supply-chain surface: the verdict you want is the one your teammates will inherit.

What CallLint does to Cursor

Offline by default. Deterministic. Never executes the server it judges. SAFE means no blockers observed, not a proof of runtime safety.

A No blockers observed verdict means exactly that — no blocker under the evidence CallLint could collect. It is not a guarantee, and Insufficient evidence never becomes it on its own. See Coverage Boundary for what this scan does not look at.

Configuration Paths

CallLint looks for Cursor configurations in:

  • ~/.cursor/mcp.json
  • <project>/.cursor/mcp.json

Authority Surfaces

Cursor can grant tools the following authority surfaces:

  • mcp
  • filesystem
  • shell
